# Talents: a passive build system for combatants

**Card:** AS-252. **Status:** proposal; nothing here is implemented.
**Sibling:** AS-253 (gameplay loop) may use talents as progression. §8 says how
the two connect.

## Recommendation in one paragraph

Ship talents as **curated rows of pick-one choices**: three new rows per class,
three options per row, all defined in `assets/config/talents.ron`. Each class's
existing pre-match choices (curse, shout, armor, aura, pet, opener, poison)
become rows in the same file, because each one already *is* a pick-one row.
A talent is data: a flat stat block priced by the item budget's own weights, a
patch to one or more `abilities.ron` fields, a granted ability, a proc on the
proc-trinket machinery, or, rarely, a bespoke mechanic. Talents act through a
per-combatant **resolved ability book**, built at spawn, so most talents need no
code: the damage, heal, aura, cooldown and AI code already read their numbers
from the `AbilityConfig` they are handed. The first card proves this on the
Warlock with one talent of each cheap kind, defaulting to "no talents" so every
baseline stays byte-identical.

## 1. What already exists: the fragment

### The seven pre-match choices

`src/states/match_config.rs` holds seven typed per-class choice enums. Each is
stored as one pair of per-slot vectors on `MatchConfig` (`team1_*`, `team2_*`):

| Class | Enum | Options | Kind |
|---|---|---|---|
| Rogue | `RogueOpener` | Ambush, Cheap Shot | picks the ability cast from stealth |
| Rogue | `RoguePoison` | Crippling (only one) | picks the weapon proc |
| Warlock | `WarlockCurse` | Agony, Weakness, Tongues | picks a curse **per enemy slot** (`Vec<Vec<_>>`) |
| Hunter | `HunterPetType` | Spider, Boar, Bird | picks the pet, and with it the pet ability |
| Warrior | `WarriorShout` | Battle, Demoralizing, Commanding | picks the shout to maintain |
| Mage | `MageArmor` | Frost, Mage, Molten | picks the self-buff |
| Paladin | `PaladinAura` | Devotion, Shadow Resistance, Concentration | picks the aura |

The Priest, Shaman and Druid have no choice.

**How a choice flows.** It goes from `MatchConfig` to the spawn functions in
`play_match/mod.rs`, which pass it field by field to `spawn_combatant`. That
writes it onto a matching `Combatant` field (`warlock_curse_prefs`,
`warrior_shout`, …), and the class AI reads that field. Headless takes the same choices as string
arrays in `HeadlessMatchConfig` (`team1_warlock_curse_prefs`,
`team1_mage_armors`, …), which `to_match_config` parses.

**How they are shown.** View Combatant draws one panel per choice, except the
poison, which has a single option and no panel. The shout, armor and aura
panels go through the generic `render_strategic_option_panel<T>`, which takes a
list of `(label, value)` pairs and a getter and setter closure. The opener, pet
and curse panels are bespoke; the curse panel draws a grid of enemy × curse.
Every option except the pet resolves to an `AbilityType` via `.ability()`, so
its icon and tooltip come from the encyclopedia. `MatchConfig::set_class`
deliberately leaves a stale choice in place when a slot changes class, since only
its own class reads it.

**What this costs per option today.** Adding a fourth Mage armor takes an enum
variant, a `name`/`description`/`ability` arm, a headless string parse arm, an AI
branch, and an entry in the panel's tuple list. Adding a choice for a new class
takes all of that plus two `MatchConfig` vectors, two resize sites, two headless
fields, two spawn reads and one `spawn_combatant` parameter. That is the cost
this proposal removes.

### Equipment: the other priced pre-match choice

Loadouts (`loadouts.ron`, `BTreeMap<ItemSlot, ItemId>`) are folded into
`Combatant` by `apply_equipment`, the one seam both spawn paths call. It adds
each item's stats, picks the auto-attack and captures proc trinkets. Every item
is priced: `item_level × 0.75 × slot multiplier` against per-stat weights
(max_health 1.0/pt, spell_power 1.5/pt, crit 300/pt, resistance 0.4/pt,
mana_regen 5.0/pt). Procs are priced at their ICD long-run uptime. `cargo test`
enforces the budget. **The talent budget in §4 reuses these weights as they
stand.**

For scale, the default Warlock loadout carries 92 HP, 122 mana, 75 SP, 1% crit
and 1 mana/s regen. At those weights that is about **334 budget points**. One
ilvl 58 head slot is worth 43.5.

## 3. Candidate system shapes

### A. Full Classic trees

Three trees per class, about 17 talents each, ranks, a 51-point budget, tier
gates.

- **Depth.** Maximal.
- **Cost per class.** About 50 talents per class, 450 in all. Talent N+1 is
  cheap only for stat and patch talents. The tree UI is a new screen.
- **Legibility.** Poor. Most points buy invisible +x%, and a watcher cannot tell
  two builds apart in a match.
- **AI.** Combinatorial. Thousands of distinct builds per class, so build-aware
  AI cannot be tested.
- **Measurement.** Unmeasurable. Builds cannot be swept one at a time, and the
  balance problem moves from 9 classes to millions of class-build pairs.
- **Budget analogy.** Holds only for the stat talents.

### B. Curated rows, pick one per row (modern WoW, MoP onward)

Each class gets R rows of 3 options. The recommendation is R = 3 talent rows,
plus that class's existing kit-choice rows.

- **Depth.** 3³ = 27 talent builds per class: real identity (sustain Warlock,
  demon Warlock, burst Warlock) without a combinatorial wall.
- **Cost per class.** 9 talents per class, 81 in all. Each row is a single data
  entry, and rendering it is shared, so row N+1 costs one RON block.
- **Legibility.** Good. Every pick is a visible decision with one icon, and §6
  requires each option to leave a footprint in the match.
- **AI.** Tractable. Each option is one toggle, so a granted ability needs one
  decision rule, and the rule can be tested in isolation.
- **Measurement.** Matches the paired-sweep design exactly. Each row is a
  3-arm paired comparison with the other rows at their default. "No dominated
  option in a row" is a falsifiable success condition.
- **Budget analogy.** Strong. A row is a budget slot, the way a head piece is,
  and its options must cost about the same.

### C. Specs plus a few passives

One spec choice per class (Affliction, Demonology or Destruction), each a fixed
bundle of three or four talents, plus the existing kit choices.

- **Depth.** Lowest: 3 builds per class.
- **Cost per class.** Same content as B, without the per-row UI.
- **Legibility.** Best. "Demonology Warlock" is a single word.
- **AI.** Easiest.
- **Measurement.** Easiest: three arms per class.
- **Budget analogy.** Weakest. A bundle's parts cannot be traded, so a bad part
  is invisible inside a good bundle.
- **Player agency.** Little. It also hard-codes which talents belong together,
  which is exactly the call a player should get to make.

### Verdict: B

B is the shape the game already has. Every existing kit choice is a pick-one
row, and View Combatant already draws three of them through one generic panel.
B keeps the zero-marginal-cost property: row N+1 is a RON block. It keeps
measurement honest: a row is a paired arm set at directional tier. It gives the
AI a bounded surface. C can be layered onto B later as **preset builds** (a
named set of picks per row: "Affliction", "Demonology") for players who want a
one-word choice. That needs no new model. A is rejected: its depth is mostly
invisible, it cannot be measured, and the AI cannot use it.

## 4. Data model

### Files and types

`assets/config/talents.ron` defines talents and rows. It is loaded and
validated by a `TalentConfigPlugin` in both modes, and panics on invalid data,
like `MovementConfigPlugin`.

```ron
(
    talents: {
        DemonicEmbrace: (
            name: "Demonic Embrace",
            class: Warlock,
            icon: "icons/talents/spell_shadow_metamorphosis.jpg",
            effects: [ Stats(( max_health: 37.0 )) ],      // priced: 37 x 1.0 = 37
        ),
        ImprovedDrainLife: (
            name: "Improved Drain Life",
            class: Warlock,
            icon: "icons/abilities/spell_shadow_lifedrain02.jpg",
            budget: Some(35.0),                              // declared: not formula-priceable
            effects: [
                Patch(on: Ability(DrainLife), field: ChannelDamagePerTick, op: Mul(1.3)),
                Patch(on: Ability(DrainLife), field: ChannelHealingPerTick, op: Mul(1.3)),
            ],
        ),
        ShadowMastery: (
            name: "Shadow Mastery", class: Warlock, icon: "...", budget: Some(36.0),
            effects: [ Patch(on: School(Shadow), field: DamageAndDot, op: Mul(1.15)) ],
        ),
        SiphonLife: (
            name: "Siphon Life", class: Warlock, icon: "...", budget: Some(40.0),
            effects: [ Grant(SiphonLife) ],   // `SiphonLife` lives in abilities.ron, `talent: true`
        ),
        Nightfall: (
            name: "Nightfall", class: Warlock, icon: "...", budget: Some(35.0),
            effects: [ Proc((
                trigger: DotTick(Corruption), chance: 0.10,
                effect: NextCastInstant(Shadowbolt), duration: 10.0, internal_cooldown: 0.0,
            )) ],
        ),
        SoulLink: (
            name: "Soul Link", class: Warlock, icon: "...", budget: Some(40.0),
            effects: [ Mechanic(SoulLink(redirect: 0.20)) ],
        ),
        CurseOfAgonyPick: (
            name: "Curse of Agony", class: Warlock, icon: "...",
            effects: [ Grant(CurseOfAgony) ],    // a kit-choice option is a Grant
        ),
        // ...
    },
    rows: {
        Warlock: [
            (id: Curse,    name: "Curse",    per_enemy: true,
             options: [CurseOfAgonyPick, CurseOfWeaknessPick, CurseOfTonguesPick],
             default: Some(CurseOfAgonyPick)),
            (id: Sustain,  name: "Sustain",
             options: [SiphonLife, DemonicEmbrace, ImprovedDrainLife], default: None),
            (id: Demon,    name: "Demon",
             options: [SoulLink, FelStamina, MasterDemonologist],      default: None),
            (id: Affliction, name: "Affliction",
             options: [Nightfall, ShadowMastery, CurseOfExhaustion],   default: None),
        ],
    },
)
```

### The five effect kinds, cheapest first

1. **`Stats(...)`** uses the same stat fields as `ItemConfig`: max_health,
   spell_power, crit_chance, the resistances, mana_regen and so on. They are
   folded in the same `apply_equipment`-style pass, and **priced by the item
   budget's own weight function**, so a stat talent's budget is computed rather
   than declared. Flat values, not percentages: they price exactly, and a
   percentage of a gear-dependent total would make a talent's worth depend on the
   loadout. Classic's "+15% Stamina" becomes the flat HP that 15% buys on the
   default loadout. `PetStats(PetType, ...)` is the same thing for a pet.
2. **`Patch(on, field, op)`** rewrites a field of one or more `AbilityConfig`s:
   `on` is `Ability(X)` or `School(S)` (each owned ability of that school), `field` is an
   **exhaustive** `AbilityField` enum (DamageBase, DamageCoefficient,
   HealingBase, HealingCoefficient, ManaCost, Cooldown, CastTime, Range,
   AuraMagnitude, AuraMagnitudeCoefficient, AuraDuration,
   ChannelDamagePerTick, ChannelHealingPerTick, plus a DamageAndDot
   convenience), and `op` is `Add(f32)` or `Mul(f32)`. It has no string field
   names: a new `AbilityConfig` field the compiler cannot route is a
   compile error, not a silently ignored patch. Patches are applied in RON order,
   adds before multiplies, into the resolved book below.
3. **`Grant(AbilityType)`** adds an ability to the combatant's book. The ability
   is an ordinary `abilities.ron` entry with `talent: true`, so the encyclopedia,
   the icon, `ability_text` prose and `lands_silently_audit` all reach it as they
   reach any ability. The kit-choice rows use `Grant` too: "Curse of Agony" is
   the talent that grants Curse of Agony.
4. **`Proc(ProcConfig)`** is the trinket `ProcConfig`, widened. New triggers:
   `DotTick(AbilityType)` and `CritTaken`. New effects: `NextCastInstant(AbilityType)`
   and `NextCastFree`. The effects are not stat auras, so they cannot be priced by
   uptime; a talent proc declares its budget instead. The proc buff carries
   `Aura::source_talent` exactly as a trinket proc carries `source_item`, so the
   buff bar, the frames and the encyclopedia show the talent's icon.
5. **`Mechanic(TalentMechanic)`** is an exhaustive enum of bespoke rules (Soul
   Link, Spirit of Redemption), each with its own code site. It is a last resort,
   and every row should have at most one. It is the only kind whose N+1 is not
   free.

### The resolved ability book

The one structural change. Today every call site reads the global
`AbilityDefinitions` (about 470 references, 125 `get_unchecked`). Talents need
*this combatant's* Drain Life. At spawn, each combatant gets an `AbilityBook`
component:

- its class's `AbilityConfig`s,
- plus its granted abilities,
- with every patch applied.

`calculate_ability_damage_config`, `calculate_ability_healing_config`,
`AuraPending::from_ability_scaled`, cooldown setting and mana charging already
take an `&AbilityConfig`. A call site that fetches that config from the
combatant's book changes behaviour with **no other edit**, and that covers the
AI's mana and cooldown reads too.

Migration is incremental:

1. A combatant with no talents gets a book identical to the global table, so
   unmigrated sites are still correct for it.
2. Phase 1 migrates the casting, channel, aura-tick and AI paths the Warlock's
   phase-1 talents reach.
3. A `talent_book_audit` test, in the shape of `heal_site_audit`, then pins
   `AbilityDefinitions::get` out of sim paths that have a combatant to hand.

**What the book is not:** a place for runtime buffs. A patch is resolved once,
at spawn, and never changes during a match. Anything that changes during a
match is an aura.

### Storage: one `Build` per slot

```rust
pub struct Build { pub picks: BTreeMap<RowId, Pick> }
pub enum Pick { One(TalentId), PerEnemy(Vec<TalentId>) }   // PerEnemy: the curse row
```

The seven per-class vector pairs on `MatchConfig` collapse into
`team1_builds` and `team2_builds`, each a `Vec<Build>`. The headless JSON gains
`"team1_builds": [{"Sustain": "SiphonLife", "Curse": ["CurseOfAgonyPick", "CurseOfTonguesPick"]}]`.
The old fields stay parsed and are mapped into builds, so every committed sweep
JSONL still replays. The typed enums retire into data, and the AI asks the book
which curse it has, not a `WarlockCurse`. `set_class` keeps its current rule: a
stale pick for another class is inert. `BTreeMap` is deliberate. AS-58 showed
that folding floats out of a `HashMap` wobbles across processes, and talents
fold stats.

### Validation, in `cargo test`

- Every talent is in exactly one row of its own class.
- A row's options all belong to its class, and its default is one of its options
  or `None`.
- A `Stats`-only talent has no `budget:`; its price is computed.
- Every other talent has a declared `budget:`.
- **Row parity:** each option's price is within 15% of its row's mean. That is
  the item budget's tolerance idea applied to a row.
- A `Grant` names an ability with `talent: true`, and every `talent: true`
  ability is granted by exactly one talent.

## 5. Two worked classes

**Scale.** Classic rank-max Corruption is 822 damage ([25311](https://www.wowhead.com/classic/spell=25311));
ours is 60. So a Classic number scales by about **0.073**. Cooldowns longer
than a match are cut by the Death Coil precedent (2 min → 30s, ÷4). The row
budget used below is **about 36 points**, a little under one ilvl 58 head
slot. §9 decision 4 asks what share of power talents should hold.

### Warlock: closing the 2v2 floor

The Warlock is the 2v2 competitive floor at **40.0%** and sits at 44.7% in 3v3
(`2026-10-10-as164-milestone-sweep.md`). It is strong as a third DPS in Mage
cleaves: Mage+Paladin+Warlock is the #1 3v3 comp at 76.6%. That makes it weak
where it is a lone target. The `combatant.rs` base-stat comment already names
the cause: "dies first", with no defensive cooldown. The rows below give it
survival choices. Classic numbers come from §2.

Default-loadout Warlock: **372 HP, 302 mana, 120 SP**. The Felhunter spawns at
0.45 × owner HP, so **167 HP**.

**Row: Curse (kit choice, per enemy).** Agony, Weakness or Tongues, unchanged.
This is today's panel, re-expressed as a row.

**Row: Sustain**

| Option | Classic | Proposed here | Kind | Price |
|---|---|---|---|---|
| Demonic Embrace | +15% Stamina | **+37 max HP** (372 → 409, +10%). Applied before the pet spawns, so the Felhunter gains +17 through its 0.45 ratio, as it already does from gear | Stats | **37** (computed) |
| Siphon Life | 45 every 3s for 30s, 365 mana | **5 per 3s for 30s = 50 Shadow damage, healed to the Warlock**; 25 mana; Magic. A straight 0.073 scale gives 3.3 a tick; rounded up so the heal reads above the noise | Grant + a new `leech` field on the aura | 40 (declared) |
| Improved Drain Life | +2%/rank, 10% max | **+30% drain**: 10 → 13 a tick, so a full channel deals and heals 65, not 50. The rank is raised to hold the row's budget | Patch | 35 (declared) |

`leech: Some(1.0)` on an `applies_aura` block is a new general field, like
`bloom` and `stacking`. Each tick heals the caster by the damage dealt, through
`apply_healing`, so dampening and Mortal Strike apply. Death Coil's hand-coded
lifesteal in `projectiles.rs` becomes its second user.

**Row: Demon**

| Option | Classic | Proposed here | Kind | Price |
|---|---|---|---|---|
| Soul Link | 30% of the caster's damage goes to the demon; +3% damage | **20% of the Warlock's damage taken is dealt to the Felhunter instead**, while the Felhunter lives. No damage rider, because +3% leaves no footprint | Mechanic | 40 (declared) |
| Fel Stamina | demon health | **Felhunter +30% max HP** (167 → 217) | PetStats | 36 (declared, pet HP unpriced by items) |
| Master Demonologist (Felhunter) | +0.2 all resists per level | **+15 to all six resistances**, on the Warlock and the Felhunter | Stats | **36** (computed: 15 × 6 × 0.4) |

Why 20%, not Classic's 30%: at 30%, Soul Link gives the Warlock 372 / 0.7 =
**531 effective HP (+43%)** until the Felhunter has soaked 159. That is several
times what any row-mate buys. At 20% the Warlock has 465 effective HP (+25%)
and the Felhunter soaks 93. That is still the strongest survival option, and
the sweep must hold it to row parity. Soul Link also changes what the AI should
do with the Felhunter (§6).

**Row: Affliction**

| Option | Classic | Proposed here | Kind | Price |
|---|---|---|---|---|
| Nightfall | 4% per Corruption or Drain Life tick: next Shadow Bolt instant (Shadow Trance) | **10% per Corruption tick → Shadow Trance for 10s**. Six ticks give a 47% chance of at least one per Corruption. Classic's 4% fires about once a match here | Proc (`DotTick`, `NextCastInstant`) | 35 (declared) |
| Shadow Mastery | +10% Shadow | **+15% Shadow damage and drain**. At 10%, Shadow Bolt alone (15 + 0.85 × 120 = 117 per cast) gains 11.7, which is 13.8 SP or 21 points. 15% prices about 31 points from Shadow Bolt, plus the DoTs | Patch (`School(Shadow)`) | 36 (declared) |
| Curse of Exhaustion | −10% movement for 12s (TBC 30%) | **adds Curse of Exhaustion to the Curse row's options**: 30% slow for 12s | Grant | 30 (declared) |

**What the Warlock gains.** A sustain-and-demon build (Siphon Life + Soul Link
+ Shadow Mastery) adds:

- about **+25% effective HP** while the Felhunter lives, from Soul Link;
- **50 healing per 30s Siphon Life** (about 75 over a 45s life if it is kept
  up);
- about 15% more Shadow damage.

Against the "dies first" failure, that is roughly the difference between dying
to one Mortal Strike window and surviving it. This build is about 116 budget
points: three rows of about 36–40, or 35% of the Warlock's gear.

**Talents alone do not close the gap.** If every class gets three rows at the
same budget, the Warlock rises and so does everyone else. The gap closes only
if the Warlock's talents hit its binding constraint, survival under focus, more
efficiently than other classes' talents hit theirs. Failing that, the
row budget has to be a per-class knob: `rows: { Warlock: (budget: 40, rows: [...]) }`.
That makes talents a priced balance lever, as items already are. §9 decision 4
covers this. Watch the 3v3 canary while doing it: a sturdier Warlock also
raises Mage+X+Warlock, which is already the top of the 3v3 table.

### Priest: build identity for a healer

The Priest is mid-pack (52.3% 2v2 competitive). It is the worked healer
because Classic Discipline and Holy split it into two clearly different healers.
The Priest has no kit-choice row today. Default loadout: **342 HP, 280 mana,
117 SP**. Flash Heal averages 17.5 + 0.75 × 117 = **105**. PW:Shield absorbs
25 + 0.4 × 117 = **72**.

## 6. AI, legibility and measurement

### The AI

Each kind asks something different of the AI:

- **Stats and patches need nothing.** The AI already reads cost, cooldown and
  magnitude from the config it is handed. Once those reads go through the
  book, Improved Psychic Scream's shorter cooldown is used automatically.
  Hard-coded thresholds, such as an HP fraction for Drain Life, do not adapt,
  and that is acceptable.
- **A granted ability needs one decision rule**, with the standard trace
  instrumentation: `builder.reject` and `builder.choose`. A `talent_ai_audit`
  test, like the exhaustive classification in `stealth_enforcement`, fails
  until every `talent: true` ability is reachable from its class's
  `decide_action`. A talent nobody can use cannot ship.
- **A proc that changes the next cast needs one priority line.** Shadow Trance
  up means Shadow Bolt goes next. That line is one sentence, and it is where
  "builds change what the AI should do" first shows up.
- **A mechanic can need real strategy.** Soul Link makes the Felhunter a damage
  sponge, so the AI should keep it alive and near the Warlock rather than spend
  it. That is phase-4 work, gated like every new behaviour (`ai-profile-swappable`).

Each trace's header records the build, so a trace explains itself.

### Legibility: every talent must leave a footprint

Talents are for someone watching an autobattler. **A talent must show in the
match as one of these:**

- an ability cast, which reaches the timeline;
- an aura, with its icon in the buff bar (procs carry `source_talent`);
- a logged event.

Patch and stat talents show before the match instead. The tooltips show the
talented numbers, because `ability_text` generates prose from the
`AbilityConfig` it is given, and that is now the book's patched copy. This rule
is why Soul Link drops its +3% rider and why Classic's +1% talents are out.

### Measuring builds

A build is a JSONL field, so the paired-sweep pipeline takes it unchanged. Both
arms run the same cells and seeds and differ only in one slot's build. Per row:

- `gen_sweep.py` gains `--build-arm Warlock:Sustain=SiphonLife`, which emits
  the affected cells with that pick.
- One arm per option is compared against the default with `paired_sweep.py
  --tier directional`.
- The success condition is **row parity: no option dominated by another at
  directional tier**. Each row then has to defend its own budget numbers.
- Rows are measured one at a time. Factorial runs are only for a suspected
  interaction (Soul Link with Fel Stamina is the obvious one).

**Cost.** A one-class 2v2 directional sweep is about 2,330 matches an arm.
Nine option arms plus a baseline come to about 23,000 matches, or about 3–4
hours at 2 matches per second, per class. The canonical baselines are rerun only
if the default build changes (§9 decision 3).

## 7. How it reaches the player

- **Pre-match (View Combatant).** One `render_row_panel`, generalized from
  `render_strategic_option_panel`, draws every row from `talents.ron`: a title,
  three icons, the current pick highlighted. Every icon goes through the
  encyclopedia's linked-icon widget, so hovering shows the talent's tooltip and
  clicking opens its page. The bespoke curse grid becomes the `per_enemy` row's
  rendering. Row N+1 needs no UI code. Presets (shape C) are one dropdown above
  the rows.
- **Encyclopedia.**
  - A new `Topic::Talent(TalentId)` and a Talents section, registered with one
    `build_registry` call.
  - Class pages list their rows.
  - A talent page's prose is generated from its effects. Stat sentences reuse
    the item stat text. Patch sentences read "Drain Life drains 30% more". Grants
    link the ability page. Procs reuse `proc_description`.
  - A talent-granted ability's page carries a "Talent" badge.
  - A proc buff and its talent each appear as a Buffs & Debuffs entry, as trinket
    procs already do.
- **Combat log.** A `[TALENTS]` line at spawn, beside `[EQUIPMENT]`:
  `[TALENTS] Team 1 Warlock: Curse=Agony/Tongues, Sustain=Siphon Life, Demon=Soul Link, Affliction=Nightfall`.
  Soul Link logs its redirect, and procs log as trinket procs do. The Results
  screen shows each combatant's picks under its name.
- **Replay.** The build is part of the replay config JSON, so a replay
  reproduces the match.

## 8. Connection to the gameplay loop (AS-253)

The sim only ever sees a `Build`, and progression decides **which builds the UI
offers**. That keeps all progression state outside the deterministic sim, and
replays carry only the build. Rows map naturally onto a loop:

- A rostered character unlocks a row at a milestone.
- An option can be a reward.
- Respec is either free between matches, which suits a ladder, or locked for a
  run, which suits a roguelite.

Sandbox and skirmish modes offer every row. Nothing in this model needs
changing to support any of those; the loop card picks the policy.

## 9. Decisions for the user

1. **Shape.** Curated rows (B) as recommended, or spec bundles (C) only?
2. **Baked-in talents.** Mortal Strike, Ice Barrier, Holy Shock, Swiftmend and
   Unstable Affliction are Classic or TBC talents shipped as baseline. The
   recommendation is to **keep them baseline**: talents only add, and no class
   loses a button it has today. The alternative is to move them into rows, which
   is more faithful and gives the rows real capstones, but re-baselines every
   class at once.
3. **Default build.** The recommendation is **no talents by default** until
   every class has rows. Talents are then opt-in, and every baseline and
   byte-identity gate holds. The alternative is a shipped default build per
   class, which needs a new AUTHORITY baseline when it lands.
4. **Talent power share and per-class budgets.** Talents could be worth about
   one gear slot per row (about 36 points, so three rows are about a third of
   the gear budget), or less. Should the row budget be equal for every class, or
   a per-class balance lever (more for the Warlock, less for the Paladin, which
   is at 63.1% in 2v2 competitive)?
5. **Classic or TBC sources.** Soul Link, Pain Suppression and Curse of
   Exhaustion's 30% are TBC-shaped. The project's rules intuition is TBC
   (`tbc-is-the-rules-intuition`). Confirm that talents may draw from either era.
